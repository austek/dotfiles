This repository contains my personal configuration files (dotfiles) for my Ubuntu-based development environment.
It is designed to be automated, preset-aware, and easily deployed on a new machine.

The core of this setup uses *GNU Stow* to manage symlinks and the `dotfiles-setup` Python CLI to orchestrate the entire installation, including applications, repositories, and preset-specific settings.

== Key Features

* *GNU Stow*: Uses `stow` to manage all dotfiles, keeping them neatly organized in this repo and symlinked to their correct locations in `$HOME` or `/`.
* *Preset-Aware Setup*: `dotfiles-setup install` takes a `--preset work`, `--preset personal`, or `--preset homelab` argument (and reuses the saved preset on later runs).
It then installs the correct applications and builds the right configuration files based on this preset (see "Presets and the Private Overlay" below for how presets are resolved and extended).
* *Declarative `apt` Sources*: All third-party `apt` repositories (like Google Chrome, VS Code, 1Password) are declaratively managed using `.sources` files in the `apt/` package.
The setup script securely downloads the latest GPG keys during installation.
* *Snap-Free*: `snapd` is automatically removed and blocked via an `apt` preference file (`system/` package) for a cleaner system.
* *Zsh Function Autoloading*: Custom Zsh functions are stored in `~/.config/zsh/functions` and loaded efficiently using `fpath` and `autoload`.
* *Zsh Completions*: Tab-completion scripts for custom commands live in `$ZSH_CUSTOM/completions` (`omz/.oh-my-zsh/custom/completions/`), which oh-my-zsh adds to `fpath` before `compinit` — e.g. `_flaky-it` and `_kdev`.
* *Automated Binary Installation*: Downloads and installs specific `.deb` packages from GitHub releases (like `lsd` and `bat`) based on a text list.
* *Secure & Separate Configs*:
** *Claude Code Profiles*: Per-preset Claude Code settings (`claude_work.json`, `claude_personal.json`, `claude_homelab.json`) live in `~/.dotfiles/claude-profiles/`. `dotfiles-setup install` merges the preset's file into the generated `~/.claude/settings.json`, after the base `claude/.claude/settings.json` and before the private overlay's `claude-settings/settings.json` and `claude-profiles/<preset>.json`.
** *Second Claude account*: `claude-burst` runs Claude Code on another account. Its config dir, `~/.claude-burst`, links in everything from `~/.claude` except the login and account file, so settings, sessions and plugins are shared. Run `claude-burst` once and `/login` with the second account.
** *Claude Remote Foothold*: on the `personal` and `homelab` presets, `dotfiles-setup install` enables user lingering and installs systemd user units that start Remote Control sessions in tmux at boot: one named after the hostname for the main account (attach with `tmux attach -t claude-foothold`), and one named `<hostname>-burst` for the `claude-burst` account once it has logged in (attach with `tmux attach -t claude-foothold-burst`). The `work` preset runs none. Which accounts get one is the preset's `footholds` list.
** *Secret Configs*: True secrets (API keys, tokens) are ignored by Git.
They should be manually placed in `~/.config/dotfiles/secrets.env` (mode 600), which both `.zshrc` and the foothold unit load.

== Installation on a New Machine

=== Clone the Repository

[source,bash]
.Install git first
----
sudo apt update && sudo apt install git -y
----

[source,bash]
.Then, clone this repository to your home directory as `.dotfiles`.
----
git clone <your-repo-url> ~/.dotfiles
----

=== Run the Setup Script

[source,bash]
.Bootstrap this machine from your home directory, specifying the machine preset.
----
~/.dotfiles/bin/dotfiles-setup install --preset work
# or
~/.dotfiles/bin/dotfiles-setup install --preset personal
# or
~/.dotfiles/bin/dotfiles-setup install --preset homelab
----

After checking `~/.claude/settings.json` for hand edits since the last install (stops with exit 3 unless `--accept-drift`), it fetches this repo, and
the `~/.dotfiles-private` overlay when it is a git checkout, and fast-forwards each when new commits exist, so
presets and package lists are current; a failed fetch or
fast-forward (dirty tree, diverged branch) only warns. The first time you run it for a preset on this
machine it prompts for your git name, email, and (optionally) an SSH signing key, and writes them to
`~/.gitconfig.local`; it resolves the preset's package lists, minus your opt-outs in
`~/.config/dotfiles/packages/<preset>.txt`; and it detects any `~/.dotfiles-private` overlay and layers
it in (see "Presets and the Private Overlay" below for all three). It then runs the install steps itself
to actually install packages, stow the dotfiles, and configure your Claude Code profile — which is where
the `sudo` password prompt and the rest of the guided process come from. If a step fails, it offers to roll
back the changes it recorded in `~/.dotfiles-setup-rollback.log` (stowed packages, backed-up and generated
system files, docker group membership) and to reinstall the apt and Flatpak packages it removed. Removed
`.deb`-backed packages (Slack, Zoom, GitHub pins) only get a warning to reinstall them manually, and
packages the install added are not uninstalled.

`dotfiles-setup install` also accepts `--dry-run`, `-v`/`-vv`/`-vvv` (verbosity), `--reconfigure` (re-prompt for the git identity), `--accept-drift`, and `--prune` (remove no-longer-wanted packages without the confirmation prompt; apt removals run only in the system stage).

[NOTE]
If stow fails because existing files block a symlink, re-run with `--force`. Each blocking file moves to
`~/.local/state/dotfiles/stow-backups/<timestamp>/<path relative to $HOME>` and is logged, so restoring it
is a plain `mv`.

[NOTE]
If you get a "Permission denied" error, your clone may not have preserved the executable bits.
Run `chmod +x ~/.dotfiles/bin/dotfiles-setup ~/.dotfiles/bin/dotfiles-backup` and try again.

=== Manual Steps

==== Add Secrets
If you have any secret keys, tokens, or private environment variables, add them to `~/.config/dotfiles/secrets.env` as plain `KEY=value` lines, with no `export` prefix and no `$` or backslashes in values:

[source,bash]
.Example:
----
install -m 600 /dev/null ~/.config/dotfiles/secrets.env
echo "GITHUB_TOKEN='your-secret-token'" >> ~/.config/dotfiles/secrets.env
----

==== Git Configuration

The setup stows `~/.dotfiles/git/.gitconfig` to `~/.gitconfig`, which carries no identity of its own. Running `dotfiles-setup install --preset <name>` (above) is what supplies it: the first time you run it on a machine, it prompts for your git name, email, and (optionally) an SSH signing key, and writes them to `~/.gitconfig.local`, which `.gitconfig` includes unconditionally. `.gitconfig` also conditionally includes `~/.dotfiles-private/git/gitconfig-work` — from the optional private overlay described below — to override `user.email` when your remote points at a Collibra `github.com` repo.

=== Restart Your Shell

Open a new terminal or run `zsh` to load your new environment.

== How to Maintain This Repo

=== Updating Applications

To add or remove applications, *do not* use `apt-get install` directly.
Instead, edit the package lists in the `~/.dotfiles/packages/` directory:

* `apt_common.txt` — all presets
* `apt_desktop.txt` — GUI packages, only pulled in by `work`/`personal`
* `apt_rust.txt` — Rust tooling, only pulled in by `personal`/`homelab`
* `apt_work.txt`
* `apt_personal.txt`
* `apt_homelab.txt`
* `github_bins.txt`

Re-run `dotfiles-setup install` to pick up the change: it installs what a list gained and, after a confirmation prompt, uninstalls what a list dropped. To skip a package on one machine only, add it to that machine's opt-out file instead — see "Presets and the Private Overlay" below.

=== Updating Configuration Files

. *Change Configs*: Edit the files directly in their `stow` packages (e.g., `~/.dotfiles/zsh/.zshrc` or `~/.dotfiles/claude-profiles/claude_work.json`).

. *Run `dotfiles-backup save`*: This helper script will automatically add all changes (aborting first if `scripts/validate-no-machine-paths.sh` fails or `claude/.claude/settings.json` has uncommitted changes; use `/claude-settings-split` for the latter), commit them with a standard message, push the current branch (creating `backup/<timestamp>` when on `main`), and open a pull request if none exists. `main` is protected, so merge the PR once CI is green, then run `git switch main && git pull`.
+
[source,bash]
.Run the backup script to commit changes and open a PR.
----
dotfiles-backup save
----

=== Stowing and Unstowing Packages

To manually manage packages, you can run `stow <package-name>` or `stow -D <package-name>` from the `~/.dotfiles` directory.

* `stow <package-name>`: Creates the symlinks for the package.
* `stow -D <package-name>`: Deletes the symlinks for the package.

[NOTE]
`dotfiles-setup install` handles stowing automatically. This manual method is only for quick adjustments or troubleshooting.

Packages listed in `.stow-packages` are stowed unfolded (one symlink per file) so that new files appear without a restow.
`gradle` is the one exception and stays folded — `gradle/.gradle` is the live Gradle home, and unfolding its ~1.1M cache files would exhaust `stow` before it wrote anything.
`claude` is unfolded like the rest (rather than folded for convenience) specifically so the private overlay below can also contribute files under it without two source directories fighting over one top-level symlink.
`dotfiles-setup` refuses to unfold any package over 1000 files rather than attempting it.

=== Claude Code Skills

Shareable Claude Code skills and commands live in a separate public repo, https://github.com/austek/ustekai-skills[austek/ustekai-skills], packaged as a Claude Code plugin marketplace named `ustekai-skills` (plugin keys read `<plugin>@ustekai-skills`) and referenced from `claude/.claude/settings.json`.
This repo carries no vendored skills or commands of its own.
Add a new skill there, not here.

== Presets and the Private Overlay

=== Presets

A *preset* is a manifest at `presets/<name>.json` that lists which package files (from `packages/`) to install, any backend-specific package-name overrides (e.g. for `apt`), and which `claude-profiles/*.json` file supplies Claude Code settings. This repo ships three — `work`, `personal`, `homelab` — and the set is extensible: drop in a new `presets/<name>.json` to add a machine type, no code changes required.

Running `dotfiles-setup install --preset <name>` installs the preset's package files plus the overlay's extras, minus the names in `~/.config/dotfiles/packages/<name>.txt`. That file holds only your opt-outs for this machine, one name per line, under the header `# dotfiles-setup opt-outs v1`. It is yours to hand-edit; the install never regenerates it. A missing file means no opt-outs.

The install records what it applied in `~/.config/dotfiles/state.json`. On the next run, a package that is no longer wanted and is still installed — because a list dropped it or you opted out of it — is listed and removed only after you confirm. `--prune` confirms without asking; a non-interactive run without it, or a declined prompt, removes nothing and asks again next time; `--dry-run` only lists. Ctrl-C at the prompt stops the install before any step. apt packages, Slack, Zoom and GitHub pins are removed through apt, only in the system stage (`--no-system` skips them with a warning), never cascading to other packages and never with `autoremove`. A package that moved to another manager, e.g. a pin now listed as an apt package, is kept. Other vendor-script installs (e.g. SDKMAN, nvm) are reported for manual removal. Removals that did not happen are listed and offered again next run. Any Flatpak install failure, or a saved overlay that is now missing, skips all removals for that run; an overlay found at a new path is used and its path saved.

After a successful install, switching presets moves the other presets' opt-out files to `~/.local/state/dotfiles/package-backups/<timestamp>/`. A full package list from an older version of this repo is converted once to an opt-out file, with a backup in the same place; installed packages that only that old list named are offered for removal on that run.

=== The Private Overlay

An optional sibling clone at `~/.dotfiles-private` (or a path given via `DOTFILES_PRIVATE_ROOT`) is auto-detected and layered on top of this public repo for anything that shouldn't live here. If you already have such a repo, bootstrap it with:

[source,bash]
----
dotfiles-setup private clone --repo git@github.com:you/dotfiles-private.git
----

This clones straight to `~/.dotfiles-private` (override with `--dest`) and refuses to run if that path already exists, so it never overwrites an existing clone or unrelated directory — update an existing clone with a plain `git -C ~/.dotfiles-private pull` instead. Once cloned, the next `dotfiles-setup install --preset <name>` auto-detects it and layers in everything below:

* *Full git identity, no prompt* — if `~/.dotfiles-private/git/gitconfig.local` exists, `dotfiles-setup install` symlinks `~/.gitconfig.local` straight to it instead of interactively prompting for name/email/signing key. Use `~` (not an absolute `/home/<user>` path) for the signing key so the same private repo stays portable across your own machines.
* *Work-remote override* — `~/.dotfiles-private/git/gitconfig-work` is conditionally included by `git/.gitconfig` on Collibra remotes (see "Git Configuration" above).
* *Extra packages* — `~/.dotfiles-private/packages/<preset>_extra.txt` is unioned into the resolved package list for that preset; opt-outs in `~/.config/dotfiles/packages/<name>.txt` apply to these names too.
* *Extra Claude settings* — `~/.dotfiles-private/claude-profiles/<preset>.json` is deep-merged into the generated `~/.claude/settings.json` last, over this repo's own `claude-profiles/<preset>.json`; lists union.
* *Private stowed files* — after stowing this repo's own `.stow-packages`, `dotfiles-setup install` also reads `~/.dotfiles-private/.stow-packages` and stows those packages (unfolded, `stow --override='.*'`, from the private repo) onto `$HOME` too. `--override` lets a private file win over a public one at the same path, not just add new ones — e.g. a private `claude/.claude/CLAUDE.md` with org-specific instructions this machine's user isn't free to publish replaces this repo's generic one, while `claude/.claude/skills/*` (private-only skill directories) and `local/.local/bin/*` scripts just add alongside it. Packages that belong to one preset go in `~/.dotfiles-private/.stow-packages.<preset>` (e.g. `.stow-packages.work`): that preset stows them, and every other preset runs `stow --delete` on them so links from an earlier install disappear.

If `~/.dotfiles-private` doesn't exist, none of the above applies — a plain fork of this repo runs off its public defaults alone.
